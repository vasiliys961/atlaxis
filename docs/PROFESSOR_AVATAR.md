# Профессор: текст, голос и видео

Профессор приложения остаётся единственным источником ответов: `/api/chat` → существующая проверка ответа → текст в чате → `AgentManager.speak()`. Метод `chat()` D-ID не вызывается, медицинские файлы в D-ID не загружаются. Помощь по интерфейсу доступна без ключа модели через `lib/product-guide.ts`; медицинские вопросы остаются в прежнем обработчике.

## Настройка

В D-ID разрешите конкретный домен приложения в Manage Embed. Задайте `NEXT_PUBLIC_DID_AGENT_ID` и `NEXT_PUBLIC_DID_CLIENT_KEY` из Embed. Это публичный ограниченный по доменам client key, не секретный API key. После изменения переменных пересоберите приложение. Для текущего демо ID агента: `v2_agt_4PlWJXA3`. Не размещайте неограниченный серверный ключ во фронтенде.

Пользователь нажимает «Включить видеоаватара», после подключения задаёт вопрос. Новые ответы приложения передаются в D-ID для озвучки. Подключение расходует кредиты. «Выключить», сворачивание окна и уход со страницы закрывают соединение. Видео использует `object-fit: contain`, поэтому окно не обрезает его края. Исходное кадрирование выбирается в D-ID (Standard для Frank).

«Включить озвучку» использует голосовой сервис браузера без видео и без D-ID. «Продиктовать вопрос» использует SpeechRecognition браузера с русским языком. Диктовка сначала заполняет поле, пользователь проверяет и отправляет текст сам. Распознавание работает не во всех браузерах и может использовать облачный сервис поставщика браузера. При отказе или неподдерживаемом браузере доступен письменный ввод.

Перед подключением видео показано уведомление о передаче текста в D-ID за рубеж. В демо используйте синтетические документы. Для реальных медицинских ответов нужна проверка допустимости такой передачи. Подключение к D-ID не происходит автоматически; исходные документы, история чата и вопрос не передаются из этой интеграции, только текст новых ответов при включённом видео.

## Живой разговор

Транспорт WebRTC и серверный обмен SDP переиспользуют подход из `cips-procurement-translator` (`lib/dialogue-realtime.ts`, `lib/openai-sdp-call.ts`). В Атлаксисе Realtime получает только микрофон, распознаёт русский вопрос и НЕ генерирует ответ (`create_response: false`). Завершённая расшифровка отправляется в обычный `/api/chat` текущего владельца документов. Ответ проходит существующие проверки и передаётся в `speak()` аватара; без видео используется включённая пользователем озвучка браузера. Дубли расшифровки не отправляются повторно, порядок завершённых реплик сохраняется.

На сервере нужны `OPENAI_API_KEY` и `PROFESSOR_REALTIME_ENABLED=true`. В `.env.example` указаны модели существующего переводчика. Это отдельный ключ OpenAI, ключ OpenRouter не подходит для Realtime. Исходный переводчик не изменён. До включения на публичном сервере подключите пользовательскую авторизацию и общий лимит расходов. Сейчас маршрут требует cookie владельца, same-origin и ограничивает переподключения разом в минуту на владельца в рамках одного процесса; это не полноценная защита публичного платного API.

Кнопка «Начать живой разговор» предварительно сообщает о передаче микрофона в OpenAI и автоматической отправке вопросов. Начало речи прерывает озвучку. Разговор ограничен 10 минутами на клиенте, отключается кнопкой, при сворачивании и уходе со страницы. Клиентский таймер не является серверным лимитом расходов. Для точной проверки чисел и названий лекарств сохраняется письменный ввод с ручной диктовкой. Realtime-транскрипция может ошибаться; текущая версия не является проверенным медицинским голосовым интерфейсом.

На сервере без ключа кнопка живого разговора скрыта. Внешняя интеграция и задержка требуют отдельного живого теста. Официальная документация: https://developers.openai.com/api/docs/guides/realtime-transcription и https://developers.openai.com/api/docs/guides/voice-webrtc?voice-api=realtime . Используемая модель `gpt-4o-mini-transcribe` из переводчика объявлена устаревающей; её отключение заявлено на 26 февраля 2027, до этого нужен проверенный переход на актуальный workflow, а не простая замена имени модели.

`npm test`, `npx tsc --noEmit`, `npm run build`.

Для живого теста нужны разрешённый домен, действующий client key, кредиты и доступ к сервисам D-ID. Без этих условий видео не считается проверенным. Проверьте подключение, один ответ на каждый вопрос, остановку речи, отключение, сворачивание окна, отказ микрофону и сохранение текстового ответа при ошибке видео.

Официальный SDK: https://sdk.d-id.com/ . `speak()` произносит переданный текст, не запускает модель агента.
