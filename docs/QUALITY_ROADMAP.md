# Проверяемая медицинская история ATLAXIS

## Исправление после пользовательской проверки (.9)

PDF с текстовым слоем собирается из координат фрагментов: элементы одной горизонтальной строки соединяются слева направо, страницы разделяются явным маркером. Это не OCR и не универсальное распознавание сложных таблиц; многостолбцовые документы и переносы внутри названия требуют проверки на исходных файлах. Учитываются распространённые сокращения в скобках после названия; добавлены цинк и СОЭ. Ошибки отсутствующего числа/даты вынесены из противоречий в ограничения извлечения, сгруппированные по документам. При нуле извлечённых показателей интерфейс не утверждает, что этих показателей нет в исходном документе, и не создаёт вопросы врачу из ошибок парсера.

Поиск получает названия извлечённых показателей без значений и полного контекста пациента; это библиографический этап. Непроверенный поисковый пересказ не показывается пользователю как медицинская интерпретация. В интерфейсе остаются статусы полученных первичных страниц. Каталог липидных источников показан только при наличии темы «Липиды». Сохранённые результаты .7/.8 требуют повторной загрузки исходного файла для нового извлечения. Причина отклонения пользовательских JPG без самих файлов и ответа провайдера не установлена.

## Реализовано в этом этапе

После просмотра пользовательских скриншотов исправлено разрешение переменных шрифтов: `next/font` задаёт их на `body`, а псевдонимы ранее вычислялись на `:root`, где они отсутствовали. Псевдонимы теперь задаются на `body` с запасными шрифтами. Рабочий фон нейтральный; пейзаж скрыт, карточки отчёта компактнее, статус и ссылка разнесены по строкам, действия профессора уменьшены. Повторные кнопки обсуждения у ограничений извлечения и справочных оговорок убраны. Визуальная проверка новой версии в Safari ещё не выполнена.

- Цитата открывает обезличенный извлечённый текст: выбранная строка и по три соседних строки. Текст загружается по запросу через существующий маршрут с изоляцией владельца. Оригинальный файл не передаётся. Номер строки не является номером страницы PDF. Визуальное наблюдение модели явно отделяется от цитаты автора документа.
- Для изображений просмотр и клинический контекст используют общий `sourceDocumentText`, чтобы номера строк не расходились. При несовпадении сохранённой цитаты с текущей строкой интерфейс сообщает о возможном устаревании.
- История всех структурированных числовых показателей содержит исходные значения, даты, единицы, референсы конкретного бланка и ссылки на фрагменты. Записи без даты остаются в конце; несовместимые единицы не пересчитываются автоматически. Повторные строки не объединяются без подтверждённой идентичности исследования.
- OCR больше не обрезает коллекции после 40 строк/измерений и текст после 240 символов. До 500 элементов в каждой коллекции, до 4000 символов строки, до 120000 символов всего JSON. Превышение любого предела отклоняет ответ целиком вместо публикации сокращённого результата. Невалидные элементы по-прежнему не становятся измерениями. Полнота самого ответа визуальной модели не доказана, лимит её вывода не увеличен.
- Версия обработки `.8`: старые снимки сами по себе заново не отправляются модели. Для исправления старого результата требуется повторная загрузка исходника; это платный вызов при подключённом провайдере.
- Убрано сообщение «Пояснения по темам ещё пишутся», хотя отдельная генерация по темам была отключена для экономии.

## Измеримый базовый набор

`npm run quality:baseline` запускает шесть синтетических сценариев из `fixtures/quality/baseline.json` без платных запросов. Проверяет точное совпадение концепта, числа, единицы, даты, строки и обоих референсов; считает precision/recall, неожиданные результаты и сохранение неизвестного/цензурированного показателя в клиническом контексте.

Это проверка ограниченного набора поведения парсера, не оценка клинической точности, OCR, изображений, качества рекомендаций или модельных объяснений. Аннотации подготовлены при разработке и ещё не прошли независимую врачебную проверку. Отсутствие структурированного числа для `<5` и неизвестного показателя ожидаемо: исходная запись сохраняется для общего разбора.

## Следующие критерии готовности

1. Независимая врачебная разметка разрешённых к использованию обезличенных документов. Покрыть выписки, сложные таблицы, несколько страниц, плохие фотографии, разные лаборатории и несколько дат. Хранить происхождение и статус проверки каждого примера, не включать реальные идентификаторы в git.
2. Явно запускаемый и ограниченный бюджетом API-прогон: точность OCR, полнота объяснений, корректность источников, новые диагнозы/персональные назначения, latency и фактический usage провайдера. Не подменять такую проверку одобрением второй модели. Пока нет ключа и размеченного корпуса, эти показатели неизвестны.
3. Координаты и номера страниц для PDF/OCR. Сейчас строки сохраняются, расположение в оригинале — нет. Не создавать фиктивные координаты.
4. Структурирование неизвестных маркеров и качественных/пороговых результатов с источником и подтверждением неоднозначности; контроль многостолбцовых таблиц. Не выводить диагнозы и не присваивать клинические оси только по названию неизвестного маркера.
5. Рекомендации: редакция, раздел, организация, тип источника и проверенная применимость. Сейчас проверяется только доступ к ограниченному фрагменту нескольких страниц; автоматическое подтверждение последней редакции отсутствует.
6. Мобильная проверка MP4/MOV на реальных Safari/Chrome, съёмка листов, пропуски и повторные кадры. Проверка на нескольких серверных экземплярах и защита от повторных платных вызовов. Существующее кеширование одного состояния не обеспечивает распределённое exactly-once.

Дополнительные роли моделей не добавлены; просмотр источников, таблица истории и базовый набор не вызывают модели.
